# 产品需求文档：个人开发工作台重构

## 摘要

> 下游角色请优先阅读本节，再按需求 ID 查阅细节。

- **核心目标**：把现有网站导航与 13 类开发工具整合为一个键盘优先、移动端可用的个人开发工作台。
- **目标用户**：仅项目所有者本人，强调打开速度、低操作成本、个人数据私有和跨设备连续性，不建设团队能力。
- **P0 交付**：统一首页与命令面板、网站和工具统一搜索、收藏与最近使用、导航 CRUD/排序/撤销、工具交互一致化、可靠同步与移动端重构。
- **技术约束**：继续部署于 Cloudflare Pages、继续使用 Supabase 鉴权与个人数据；P0 不执行破坏性生产库迁移。
- **验收重点**：常用目标 3 秒内可达，异常/空/加载/离线均可恢复，刷新不静默丢数据，构建、权限隔离和核心自动化测试通过。

## 1. 概述

### 1.1 背景

当前项目已经具备邮箱鉴权、个人导航云同步、分类与拖拽排序，以及 JSON、编码、网络、安全、文本、Diff、Docker 等开发工具，但仍像“导航页”和“工具集合”两个产品：

- 网站搜索位于导航页，工具搜索位于固定侧栏，用户需要先判断目标属于哪一类。
- 首页以分类卡片为主，缺少收藏、最近使用和统一快捷入口。
- 导航以整包弱类型数据直接读写 Supabase；并发保存、失败重试和离线恢复不足。
- 新增、删除分类等操作依赖浏览器原生弹窗，编辑、撤销和错误反馈不完整。
- 移动端直接将整条侧栏堆到页面上方，工具双栏或多栏布局也容易溢出。
- 工具页的输入、执行、复制、清空、示例、空结果和错误表达不一致。
- Supabase 地址存在硬编码，现有工程没有正式测试脚本和稳定错误边界。

### 1.2 产品目标

1. 将“找网站”和“找工具”收敛为一个可全程键盘操作的入口。
2. 让个人导航的管理、排序和云同步可理解、可撤销、可恢复。
3. 统一现有工具的操作语义和状态反馈，不以堆叠低频工具代替体验重构。
4. 保证桌面端高效率，同时让 360px 宽度的移动端能完成主要任务。
5. 在继续使用 Cloudflare Pages 与 Supabase 的前提下，提高类型安全、隐私和可测试性。

### 1.3 成功指标

| 指标 | P0 目标值 | 衡量方式 |
|------|-----------|----------|
| 常用目标到达时间 | 已加载页面中，打开常用网站或工具中位数不超过 3 秒 | 预置数据下完成 20 次自用任务计时 |
| 统一搜索覆盖 | 100% 现有工具及有效个人网站可由同一入口检索 | 自动化索引测试与端到端抽样 |
| 搜索响应 | 500 个网站、100 个工具的本地索引下，查询结果更新不超过 100ms | 性能测试取 95 分位 |
| 数据可靠性 | 增删改、排序、离线恢复和同步失败注入场景中 0 次静默丢失 | 集成测试与故障注入 |
| 核心工具一致性 | 13 类现有工具均有统一输入/操作/结果反馈；适用结果均可复制 | 组件清单与回归测试 |
| 移动端可用性 | 360px、768px 下无页面级横向溢出，关键任务均可完成 | 响应式端到端测试 |
| 发布质量 | Cloudflare Pages 生产构建、Supabase 鉴权与用户隔离、P0 自动化测试全部通过 | 发布门禁记录 |

### 1.4 需求穿透分析

| 层级 | 需求洞察 | 决策 |
|------|----------|------|
| 显性 | 重构项目、优化交互、增加实用功能；统一搜索网站和工具 | 命令面板与统一工作台为 P0 主线 |
| 隐性 | “自用”意味着学习成本要低、操作快、数据不被其他用户看到 | 不建设团队体系；个人隔离、快捷键和可靠同步为 P0 |
| 潜在 | 云同步失败、跨设备冲突和移动端误操作可能导致个人数据丢失 | 引入可见同步状态、本地待同步副本、重试、冲突提示和撤销 |
| 惊喜 | 不必记住工具所在分类，可从最近使用、收藏和命令面板直接回到工作上下文 | 收藏、最近使用和上下文排序纳入 P0；便笺/片段放入 P1 |

### 1.5 优先级定义

| 优先级 | 定义 | 发布决策 |
|--------|------|----------|
| P0 | 重构目标成立所必需，任何一项未验收即不得发布 V1.0 | 必须完成 |
| P1 | 高价值增强，但涉及新增数据能力或更高实现成本 | P0 稳定后实施，不阻塞 V1.0 |
| P2 | 个性化、完整离线或新增工具候选 | 后续按真实自用频率决定 |

## 2. 用户画像

### 2.1 用户画像：工作台所有者

| 属性 | 描述 |
|------|------|
| 角色 | 独立开发者、项目所有者、唯一主要使用者 |
| 特征 | 高频查资料、调试数据、转换文本；桌面键盘为主，偶尔手机访问 |
| 核心需求 | 一个入口快速访问网站与工具，并跨设备保留个人配置 |
| 当前痛点 | 搜索入口分裂、移动端侧栏难用、重复操作多、保存失败是否丢数据不明确 |
| 期望体验 | 打开即搜、少于两次点击、结果可复制、数据状态透明、出错后可恢复 |
| 隐私偏好 | 工具输入默认本地处理；未经明确提示不得上传第三方 |

### 2.2 核心场景

1. 用户按下快捷键，输入“json”或网站名称，直接进入工具或在新标签页打开网站。
2. 用户从首页收藏或最近使用区域恢复昨天的工作入口。
3. 用户新增、编辑、删除、移动网站；网络失败时仍保留修改并在恢复后重试。
4. 用户在任意工具页以一致方式粘贴、执行、复制、清空和查看错误。
5. 用户在手机上通过抽屉/底部入口和全屏搜索完成访问、收藏及基础编辑。

### FR-001：私有工作台入口与应用壳

- **描述**：当未登录用户访问工作台路由时，系统必须跳转登录页；登录成功后必须返回原目标。会话失效时不得继续展示个人云数据。
- **用户价值**：入口一致，个人内容不会因路由直达而被意外暴露。
- **依赖**：Supabase Auth、React Router。
- **验收标准**：
  - [ ] AC-1：未登录直达首页或工具路由均进入登录页，并保留安全的站内返回地址。
  - [ ] AC-2：鉴权加载期间显示骨架或明确加载态，不闪现个人数据或错误空态。
  - [ ] AC-3：会话失效后清除内存中的个人数据并提示重新登录。
  - [ ] AC-4：配置缺失时显示可操作的配置错误，不输出密钥或完整令牌。
- **边界**：存在未同步修改时退出登录，必须提示风险并允许取消；不得静默丢弃待同步数据。

### FR-002：统一工作台首页

- **描述**：登录后系统必须展示以全局搜索、收藏、最近使用、网站分类和工具分类组成的效率首页，不再要求用户先进入网站或工具分区。
- **用户价值**：打开页面即可恢复工作，不需要理解原有信息架构。
- **依赖**：FR-004、FR-005。
- **验收标准**：
  - [ ] AC-1：首页首屏包含可聚焦的统一搜索入口、最多 8 个收藏和最多 10 个最近项。
  - [ ] AC-2：每个网站或工具从首页最多两次点击可达，网站默认新标签打开，工具在当前应用路由打开。
  - [ ] AC-3：没有收藏或最近项时显示引导动作，不显示空白容器。
  - [ ] AC-4：打开目标后首页相应最近项在 1 秒内更新。
- **边界**：某条目已删除或工具路由失效时自动清理引用，并以非阻塞提示说明。

### FR-003：全局命令面板

- **描述**：当用户按下 Ctrl+K 或 macOS 的 Command+K 时，系统必须从任意工作台页面打开命令面板；移动端点击搜索入口打开全屏面板。
- **用户价值**：无需返回首页即可跳转至任意网站或工具。
- **依赖**：FR-004。
- **验收标准**：
  - [ ] AC-1：快捷键在非输入状态生效；不覆盖文本编辑器和表单的原生输入行为。
  - [ ] AC-2：方向键移动高亮项，Enter 执行，Esc 关闭并把焦点还给触发元素。
  - [ ] AC-3：空查询展示收藏、最近使用和常用工具；输入后切换为搜索结果。
  - [ ] AC-4：面板具备正确对话框语义、焦点圈定和可读的结果类型标签。
- **边界**：连续触发只保留一个面板；结果正在刷新时不得跳动到错误选项。

### FR-004：网站与工具统一搜索

- **描述**：当用户输入查询时，系统必须在同一索引内匹配个人网站与内置工具，并利用收藏和最近使用提高相关结果排序。
- **用户价值**：用户只需记住目标名称或用途，无需记住分类。
- **依赖**：导航数据、集中式工具清单。
- **验收标准**：
  - [ ] AC-1：搜索覆盖网站名称、描述、URL、分类，以及工具名称、别名、描述、分类。
  - [ ] AC-2：忽略大小写、首尾空白和连续空格；名称前缀优先于描述命中。
  - [ ] AC-3：结果清晰标识“网站”或“工具”，同一条目不重复出现。
  - [ ] AC-4：导航 CRUD 或收藏变化后，索引在 1 秒内反映最新状态。
  - [ ] AC-5：无匹配时显示“清除搜索”和“新增网站”操作，不发起外部搜索请求。
- **边界**：空名称、无效路由或无效 URL 不进入索引；搜索词不得上传到第三方。

### FR-005：收藏与最近使用

- **描述**：用户必须能够收藏网站和工具；系统必须在成功打开目标后记录最近使用的资源标识与时间。
- **用户价值**：高频入口固定可见，短期工作上下文可快速恢复。
- **依赖**：Supabase 个人数据、FR-008。
- **验收标准**：
  - [ ] AC-1：网站和工具均可收藏/取消收藏，所有入口的状态立即一致。
  - [ ] AC-2：最近使用去重并按时间倒序，默认最多保留 20 项。
  - [ ] AC-3：收藏与最近记录登录后跨设备同步，离线变化进入待同步状态。
  - [ ] AC-4：记录只包含资源标识、类型和时间，不包含查询词或工具输入。
- **边界**：底层资源删除后关联记录自动清除；目标打开失败时不写入最近使用。

### FR-006：导航分类与网站 CRUD

- **描述**：用户必须能在自定义界面中新增、查看、编辑和删除分类及网站，不得依赖浏览器原生 prompt/confirm。
- **用户价值**：个人导航可以持续维护，误操作风险可控。
- **依赖**：FR-008、网站稳定 ID。
- **验收标准**：
  - [ ] AC-1：网站支持名称、URL、描述、图标和所属分类；名称与 URL 必填并显示字段级错误。
  - [ ] AC-2：仅允许 http/https URL；缺少协议可建议补全，javascript/data 等危险协议必须拒绝。
  - [ ] AC-3：分类支持新增、重命名和删除；删除非空分类时对话框显示所含网站数量。
  - [ ] AC-4：网站支持新增、编辑和删除，保存后卡片、首页和搜索索引同步更新。
  - [ ] AC-5：元数据识别只能由明确按钮触发，并提示将 URL 发给外部服务；识别失败不阻塞手工保存。
- **边界**：同分类重复 URL 给出警告并允许取消；超长字段按名称 80、描述 240、URL 2048 字符限制。

### FR-007：排序、跨分类移动与撤销

- **描述**：在编辑模式中，用户必须能排序分类、排序网站并把网站移动到其他分类；删除和移动必须可撤销。
- **用户价值**：导航结构可快速调整，失败或误拖不会破坏已有顺序。
- **依赖**：dnd-kit、FR-008。
- **验收标准**：
  - [ ] AC-1：桌面支持指针与键盘排序；移动端提供拖拽之外的“移至/上移/下移”操作。
  - [ ] AC-2：分类内排序、跨分类移动及分类排序刷新后保持一致。
  - [ ] AC-3：删除或移动后显示至少 5 秒的撤销入口；撤销也进入正常同步流程。
  - [ ] AC-4：搜索过滤时禁用拖拽并解释原因，避免对不可见列表产生错误顺序。
- **边界**：拖拽取消不保存；同步进行中连续操作按最新本地状态串行提交。

### FR-008：云同步、失败重试与基础离线保护

- **描述**：当个人数据变化时，系统必须先进行乐观本地更新，再可靠同步至 Supabase，并持续展示“待同步/同步中/已同步/离线/失败”状态。
- **用户价值**：用户始终知道数据是否安全，网络异常时仍可继续整理。
- **依赖**：Supabase、浏览器本地持久化、现有 user_nav_configs 数据。
- **验收标准**：
  - [ ] AC-1：本地界面响应不超过 100ms，同步失败不回滚或覆盖用户刚完成的修改。
  - [ ] AC-2：失败状态提供重试；恢复网络后可自动重试，待同步修改刷新页面后仍存在。
  - [ ] AC-3：初次读取失败且有缓存时展示缓存与离线横幅；无缓存时展示错误页和重试，不误显示空导航。
  - [ ] AC-4：检测到云端与本地待同步数据冲突时，展示“保留本地/使用云端”选择和两边更新时间。
  - [ ] AC-5：所有查询按当前 auth.uid 隔离；无权数据不得进入本地缓存。
- **边界**：P0 只承诺已加载应用中的基础离线编辑与恢复，不承诺离线冷启动；破坏性数据库迁移必须另附 SQL、回滚和风险评审。

### FR-009：工具交互规范化

- **描述**：现有 13 类工具必须复用统一工具壳，形成标题/隐私说明、输入、操作、结果、反馈的固定结构。
- **用户价值**：学会一个工具即可使用全部工具，复制和纠错不再靠猜。
- **依赖**：现有工具实现、统一组件库。
- **验收标准**：
  - [ ] AC-1：适用工具均提供执行、复制结果、清空和载入示例；不适用动作不展示。
  - [ ] AC-2：Ctrl/Command+Enter 执行主操作；按钮 loading 时防止重复执行并保持输入。
  - [ ] AC-3：输入非法时显示靠近输入区的中文错误；结果为空、成功和失败有不同状态。
  - [ ] AC-4：复制成功与失败均有可访问反馈；剪贴板权限失败时允许手动选择内容。
  - [ ] AC-5：本地算法标注“仅本地处理”；任何外部 API 调用前标注目标、目的并由用户触发。
  - [ ] AC-6：重构后现有工具的核心能力无阻塞性功能回退。
- **边界**：JWT、密码、私钥等输入不得写入日志、Supabase 或默认持久化存储。

### FR-010：移动端导航与响应式工具布局

- **描述**：当视口不超过 768px 时，系统必须以顶部栏配合抽屉或底部入口替代常驻侧栏，命令面板使用全屏布局。
- **用户价值**：手机上不必先滚过完整侧栏，也能完成高频任务。
- **依赖**：响应式应用壳、FR-003。
- **验收标准**：
  - [ ] AC-1：360px、768px、1440px 下无页面级横向滚动或不可达操作。
  - [ ] AC-2：移动导航可打开、关闭、返回当前页并正确标识当前工具。
  - [ ] AC-3：双栏编辑器在窄屏按输入、操作、结果顺序堆叠，内容可独立滚动。
  - [ ] AC-4：关键触控目标不小于 44×44px，软键盘弹出后搜索结果和提交按钮仍可达。
- **边界**：不支持触摸拖拽的设备仍可通过菜单完成排序和移动。

### FR-011：全局加载、空、错误与恢复状态

- **描述**：所有异步页面和核心数据区域必须显式区分首次加载、空数据、过滤无结果、离线、同步失败、权限失败和未知异常。
- **用户价值**：不会把“还没加载”“没有数据”和“加载失败”混为一谈。
- **验收标准**：
  - [ ] AC-1：首次加载使用结构骨架；超过 10 秒显示超时说明与重试。
  - [ ] AC-2：空数据提供创建入口，过滤无结果提供清除条件，二者文案与操作不同。
  - [ ] AC-3：应用级错误边界保留返回首页/重试入口，不展示堆栈、令牌或工具输入。
  - [ ] AC-4：状态除颜色外同时使用图标与文字，并通过 aria-live 宣布关键结果。
- **边界**：重复错误提示合并，重试不得产生重复网站或重复最近记录。

### FR-012：轻量便笺与代码片段

- **描述**：P1 提供标题、正文、类型、标签、置顶、复制、搜索和 CRUD，并同步至当前用户。
- **验收标准**：
  - [ ] 新增数据表或字段前完成非破坏性 SQL、RLS、回滚方案评审。
  - [ ] 内容同步失败时保留本地草稿；不得提供公开分享或多人编辑。
  - [ ] 空标题可由正文首行生成；单条正文上限 20,000 字符并明确提示。
- **边界**：便笺可能含敏感内容，界面需提示其会上传 Supabase。

### FR-013：数据导入、导出与备份恢复

- **描述**：P1 支持带版本号和导出时间的 JSON 备份，并在导入前校验与预览。
- **验收标准**：
  - [ ] 导出包含个人导航、收藏、最近使用及已上线的便笺，不包含会话、密钥或工具输入。
  - [ ] 导入默认合并；替换模式必须二次确认并先生成可下载备份。
  - [ ] 非法、超限或版本不兼容文件不得写入任何数据，并给出字段级原因。

### FR-014：工具输入历史与跨工具传递

- **描述**：P1 可在用户主动开启后保存设备本地工具历史，并把兼容结果以内存方式发送到其他工具。
- **验收标准**：
  - [ ] 历史默认关闭、可逐工具清空，且不跨设备上传。
  - [ ] JWT、密码、私钥及证书私密材料永不进入历史。
  - [ ] “发送到”仅展示兼容目标，目标页清晰标识数据来源。

### FR-015：快捷键与首页模块个性化

- **描述**：P2 允许修改非保留快捷键、隐藏或排序首页模块。
- **验收标准**：
  - [ ] 冲突快捷键不可保存；支持一键恢复默认。
  - [ ] 个性化设置按用户同步，不影响内容数据。

### FR-016：PWA 与按需新增专项工具

- **描述**：P2 在验证使用频率后提供安装、资源缓存和离线冷启动；新增工具必须对应真实个人工作流。
- **验收标准**：
  - [ ] PWA 更新可感知且不会使用旧壳覆盖新数据。
  - [ ] 新工具须沿用 FR-009，且不得扩大为云端代码执行环境。

## 4. 非功能需求

### NFR-001：性能

- Cloudflare 生产环境桌面端首屏 LCP 95 分位不超过 2.5 秒，INP 不超过 200ms。
- 工具路由按需加载；命令面板和统一索引不得等待 Monaco 等重资源才可用。
- 同步请求开始后 150ms 内必须显示状态；网络耗时不计入本地交互响应指标。

### NFR-002：可靠性与数据兼容

- 核心写操作必须幂等或可去重；刷新、重试和 React StrictMode 不得生成重复数据。
- 上线前以生产数据副本验证旧 nav_data 的读取与迁移；未知字段保留或安全忽略。
- 任何迁移必须先备份，失败可回滚；不得以清空用户数据作为恢复方案。

### NFR-003：安全与隐私

- Supabase URL 与 anon/publishable key 从 Cloudflare 环境变量读取；前端禁止 service_role key 和硬编码生产配置。
- Supabase 表必须启用 RLS，以 auth.uid 校验 select/insert/update/delete；使用两用户测试证明隔离。
- Pages Function 代理只能访问固定 Supabase 主机与必要路径，不得成为开放代理。
- URL 必须校验安全协议；外部图标和元数据请求应限制 referrer，并在适用处提示第三方。
- 日志与错误上报不得包含访问令牌、密码、JWT、私钥、便笺正文、工具输入或完整个人 URL 清单。
- 默认不接入第三方行为分析；如未来增加，须单独说明采集字段和关闭方式。

### NFR-004：可访问性与体验

- 核心文字和控件符合 WCAG 2.2 AA 对比度；焦点清晰，不能只靠颜色表达状态。
- 命令面板、对话框、导航 CRUD、排序替代操作和工具主流程可仅用键盘完成。
- 尊重 prefers-reduced-motion；装饰动画不得延迟操作或引发持续位移。
- 禁止在 P0 核心流程使用浏览器原生 alert、prompt、confirm。

### NFR-005：兼容与部署

- 支持当前及前一主版本 Chrome、Edge、Firefox、Safari，以及 iOS Safari/Android Chrome 当前版本。
- Cloudflare Pages 需支持前端深链刷新，Pages Function 与静态资源路由不冲突。
- 发布门禁至少包含 TypeScript 构建、Oxlint、单元/组件测试、核心端到端测试和生产构建。

### NFR-006：工程质量与测试

- 导航、工具元数据、同步状态和搜索结果使用明确 TypeScript 类型；核心领域禁止新增 any。
- Supabase 访问集中于可替换的数据层，组件不得散落直接表查询。
- 自动化覆盖：搜索排序、收藏/最近、CRUD/撤销、同步重试/冲突、RLS 隔离、移动端主流程、13 类工具冒烟。
- 测试失败、构建失败或存在阻塞性 P0 缺陷时不得部署。

## 5. 用户故事

### US-001：从任意页面快速打开目标

- **作为**个人开发者，**我想要**用一个快捷键搜索网站和工具，**以便**不打断当前工作。
- **验收标准**：键盘可完成打开、选择和执行；网站与工具均有结果类型；常用任务中位数不超过 3 秒。

### US-002：安全整理个人导航

- **作为**导航所有者，**我想要**编辑分类和网站并撤销误操作，**以便**持续维护而不担心丢数据。
- **验收标准**：CRUD、跨分类移动和排序均可完成；删除/移动可撤销；刷新后结果一致。

### US-003：网络不稳定时继续工作

- **作为**跨设备用户，**我想要**看见同步状态并在失败后重试，**以便**确认修改最终被保存。
- **验收标准**：离线修改保留；失败原因和重试可见；冲突不静默覆盖。

### US-004：以相同方式使用所有工具

- **作为**高频工具用户，**我想要**每个工具都有一致的执行、复制、清空和错误反馈，**以便**减少重复学习。
- **验收标准**：13 类工具完成规范清单；敏感输入默认只在本地内存处理。

### US-005：在手机上处理临时任务

- **作为**移动端用户，**我想要**快速搜索并使用基础工具，**以便**不必依赖桌面设备。
- **验收标准**：360px 下导航、搜索、工具执行和导航基础编辑可完成且无横向溢出。

## 6. 范围定义

### 6.1 P0 范围内

- 统一应用壳、工作台首页、命令面板与网站/工具统一索引。
- 收藏、最近使用、导航 CRUD、分类与网站排序、跨分类移动、撤销。
- 乐观更新、可见同步状态、失败重试、本地待同步副本、基础冲突处理。
- 13 类现有工具的统一交互壳、反馈、隐私标识与功能回归。
- 移动端导航及响应式工具布局；加载、空、错误、离线状态。
- 配置环境变量化、RLS 隔离验证、数据层类型化和自动化测试。

### 6.2 P1/P2 候选

- P1：便笺/代码片段、版本化导入导出、默认关闭的安全工具历史、跨工具传递。
- P2：快捷键和首页模块定制、PWA/离线冷启动、经频率验证的新专项工具。

### 6.3 范围外

- 团队空间、邀请、角色权限、共享导航、协同编辑。
- 付费订阅、运营后台、公开内容站、SEO 增长和第三方广告。
- 浏览器扩展、桌面客户端、原生移动应用。
- 在线 IDE、云端代码执行、远程终端、密钥托管。
- P0 的完整离线冷启动，以及未经评审的生产数据库破坏性变更。
- 为追求数量批量新增低频工具，或复制 Raycast、Arc、Linear 的品牌视觉。

## 7. 风险与依赖

### 7.1 风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 单行 JSON 整包同步导致跨设备覆盖 | 高 | 高 | 修订号/更新时间、串行写入、冲突提示、故障注入测试 |
| 旧数据结构缺少稳定 ID | 高 | 高 | 首次读取兼容映射、迁移前备份、用 ID 代替 URL 作为交互主键 |
| 外部元数据服务不可用或泄露 URL | 中 | 中 | 改为用户显式触发、披露第三方、失败允许手工输入 |
| Monaco 等依赖拖慢首页和手机 | 中 | 中 | 路由懒加载、工具资源按需下载、独立性能门禁 |
| 重构范围过大造成工具回归 | 中 | 高 | P0 不新增低频工具，建立 13 类工具冒烟清单并分批迁移 |
| Supabase RLS 或代理配置错误 | 中 | 高 | 两用户隔离测试、固定主机 allowlist、发布前安全检查 |

| 集中式工具清单、设计令牌与统一工具组件 | 前端 | 待设计 | UI Designer / Frontend |

## 8. 开放问题与默认决策

| 问题 | P0 默认决策 | 决策门槛 |
|------|-------------|----------|
| 收藏/最近存入旧 JSON 还是新表 | 优先选择向后兼容且不破坏生产数据的实现 | Architect 在 architecture.md 定案 |
| Pages Function 代理是否保留 | 仅在网络可达性确有需要且能限制固定目标时保留 | 安全评审与 Cloudflare 预览验证 |
| 便笺是否进入首发 | 不进入 P0；仅在迁移、RLS、回滚方案齐备后做 P1 | P0 验收完成 |
| 首页模块最终视觉结构 | 保留搜索首位、收藏与最近次位的约束，具体布局由 UI 方案确定 | 360/768/1440 验收不变 |

以上问题均有可执行默认值，不阻塞下游设计和架构；任何偏离 P0 范围的方案必须显式记录取舍。
