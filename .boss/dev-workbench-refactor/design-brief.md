# 设计简报：个人开发工作台重构

## 一句话描述

将现有“网站导航 + 开发工具集合”重构为面向个人使用的统一开发工作台，让用户通过一个快捷入口搜索、调用和管理网站、工具及近期工作内容，减少日常开发中的页面跳转和重复操作。

## 目标用户

- 主要用户：项目所有者本人。
- 用户特点：高频进行开发、调试和资料检索；同时维护常用网站导航；重视操作速度、数据私有性和跨设备同步，不需要团队权限体系。

## 核心场景

1. 打开工作台后，通过全局搜索或快捷键快速找到网站、内置工具或最近使用项，并立即打开或执行。
2. 在统一界面中完成 JSON、编码、时间、网络、安全、文本、Diff、Docker 等常见开发处理，输入和结果尽量支持粘贴即用、一键复制与本地保留。
3. [假设] 管理个人工作上下文：查看最近使用、固定收藏，并保存少量临时便笺或常用代码片段，登录后通过 Supabase 跨设备同步。

## 功能范围

### 第一版必须有

- 重构整体信息架构，将导航和工具整合为统一工作台首页。
- 全局命令面板：支持快捷键唤起，统一检索网站、工具、收藏和最近使用项。
- 提升导航管理体验：添加、编辑、删除、分类、拖拽排序、收藏及可靠的同步状态反馈。
- 提升工具交互一致性：统一输入区、操作区、结果区、复制/清空/示例/错误反馈，并优化键盘操作。
- [假设] 最近使用与收藏；提供轻量的便笺/代码片段能力，并通过 Supabase 同步个人数据。
- 响应式布局：桌面端以效率为先，移动端拥有真正可用的导航方式，不再直接堆叠整条侧栏。
- 完整处理加载、空状态、错误、离线/同步中状态，并提供可恢复反馈，避免依赖浏览器原生 `prompt`、`confirm`。
- 重构数据类型、状态管理和 Supabase 数据访问层，移除硬编码配置与脆弱的 `any` 数据结构。
- 为核心交互和数据逻辑补充自动化测试，并验证 Cloudflare Pages 构建兼容性。

### 明确不做（留给后续版本）

- 团队空间、成员邀请、角色权限和共享协作。
- 付费、订阅、运营后台或面向公众的 SEO 内容站。
- 浏览器扩展、桌面客户端或移动原生应用。
- 重型在线 IDE、云端代码执行环境或远程终端。
- 未经验证便大规模增加低频工具；新增工具以真实个人工作流为依据。

## 交互方向

- 首页不是传统“卡片墙”，而是以全局搜索/命令面板、常用入口、最近使用和工具分类构成的效率仪表盘。
- 高频动作尽量控制在一次搜索或两次点击内；核心功能具备清晰快捷键和可见提示。
- 编辑模式改为局部、可撤销的操作，删除提供撤销或自定义确认对话框。
- 保存采用乐观更新但必须展示明确状态；失败时保留本地改动并允许重试，避免静默丢失。
- 工具页面共享统一组件和布局，输入内容默认仅在本地处理；涉及外部 API 时明确提示。
- 视觉上保留深色开发者工作台气质，但降低玻璃拟态和装饰动画的干扰，增强层级、可读性与无障碍对比度。

## 实用功能优先级

### P0：重构即交付

1. 全局命令面板与统一搜索。
2. 收藏、最近使用和快捷入口。
3. 网站信息新增/编辑、分类管理、拖拽排序与撤销。
4. 工具交互规范化及常用操作快捷键。
5. 同步状态、失败重试和基本离线保护。
6. 移动端导航重构。

### P1：有余量时纳入

1. [假设] 轻量便笺与代码片段，支持标签、复制和置顶。
2. 数据导入/导出与备份恢复。
3. 工具输入历史和跨工具传递，例如格式化 JSON 后直接发送到类型生成器。

### P2：后续候选

1. 自定义快捷键和首页模块排序。
2. PWA 安装、离线缓存及快速启动。
3. 仅在个人确有需求后增加新的专项工具。

## 成功标准

- 从打开页面到访问任一常用网站或工具，键盘用户可在 3 秒或少量操作内完成。
- 网站与工具均可从同一个搜索入口找到；最近使用和收藏会正确更新。
- 导航增删改、排序和同步失败均有明确反馈，刷新后不存在静默数据丢失。
- 核心工具拥有一致的复制、清空、错误与成功反馈，桌面端和移动端均可完成主要任务。
- Cloudflare Pages 生产构建通过，Supabase 鉴权与个人数据隔离通过验证。
- 核心逻辑、关键组件和主要用户路径具备可重复运行的自动化测试，无阻塞性缺陷。

## 立项时项目现状（历史基线）

> 本节记录重构开始前的仓库事实，用于解释需求来源；最终实现状态以 `tasks.md`、`tech-review.md` 和 README 为准。

- 技术栈：React 19、TypeScript 6、Vite 8、React Router 7、Supabase JS、dnd-kit、Monaco Editor、Oxlint；npm 单体前端应用。
- 部署形态（重构前）：Cloudflare Pages 前端包含宽泛的 `functions/api/supabase/[[path]].ts` Pages Function 代理；后端数据与认证使用 Supabase。最终实现已删除该代理并改为浏览器直连公开 Supabase API。
- 项目结构：`src/pages` 承载导航、登录和各类工具页，`src/components` 存放侧栏与导航卡片，`src/contexts` 管理认证，`src/lib` 直接初始化 Supabase。
- 已有功能：邮箱登录/注册、个人导航云同步、链接元数据识别、分类与拖拽排序、工具搜索、网络/IP、证书/RSA、Hash/Bcrypt、格式转换、JSON/YAML、Docker Compose、文本处理、Diff、URL/Base64/JWT、Cron/时间戳、Mock 数据/UUID、命令备忘、多媒体/二维码。
- 当前主要问题：信息架构割裂、移动端侧栏不可用、大量内联样式与弱类型、原生弹窗交互、同步并发与失败恢复薄弱、配置硬编码、缺少测试与可观测的错误边界。
- 新功能定位：重构并替换现有工作台交互，同时复用已具价值的工具实现和 Supabase 数据能力。

## 补充信息

- 参考产品方向：Raycast 的命令入口、Arc 的快速导航、Linear 的键盘效率；仅借鉴交互原则，不照搬品牌视觉。
- 用户偏好：个人自用、允许产品与功能方向由实现方合理决策。
- 硬性约束：继续兼容 Cloudflare Pages 与 Supabase；个人数据必须隔离，敏感工具输入不得无提示上传第三方。
- [假设] 第一阶段不修改生产数据库的破坏性结构；如确需新增表或迁移，必须先提供 SQL、回滚方案和风险说明再执行。
